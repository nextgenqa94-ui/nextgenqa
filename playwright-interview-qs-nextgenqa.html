What is Playwright? How is it different from Selenium?
▼
Playwright is a modern browser automation framework by Microsoft. It supports Chromium, Firefox, and WebKit with a single API.
FeaturePlaywrightSelenium
Auto-wait✅ Built-in❌ Manual waits needed
BrowsersChromium, Firefox, WebKitAll browsers via WebDriver
SpeedFasterSlower
Network Mock✅ Built-in❌ 3rd party needed
Trace/Debug✅ Trace Viewer❌ Limited
LanguageJS/TS, Python, Java, C#Same + more

03
What is page, context, and browser in Playwright?
▼
These are the 3 core objects in Playwright — nested hierarchy:
// browser → context → page const browser = await chromium.launch(); // Browser process const context = await browser.newContext(); // Isolated session (cookies, storage) const page = await context.newPage(); // A single tab
Browser — the actual browser instance (Chromium/Firefox/WebKit)
Context — like an incognito window. Each context has its own cookies, localStorage, sessions. Used for multi-user testing.
Page — a single browser tab/window. Most interactions happen here.

Difference between locator() and elementHandle()?
▼
Featurelocator()elementHandle()
Auto-wait✅ Yes — retries automatically❌ No — snapshot at that moment
Lazy✅ Evaluated on action❌ Resolved immediately
Recommended✅ Yes (modern)❌ Legacy, avoid

💡 Always prefer locator() over elementHandle() in modern Playwright.
05
How does Playwright handle auto-waiting?
▼
Playwright automatically waits for elements to be in the right state before performing actions. This is called actionability checks.

Before click(), Playwright checks: visible stable enabled not obscured
// No manual wait needed — Playwright waits automatically await page.locator('#submit').click(); // waits until button is visible + enabled // Default timeout: 30 seconds (configurable in playwright.config)

07
What are frameLocator and page.frame()? When to use which?
▼
frameLocator() — modern, chainable, uses CSS/XPath selector. Preferred approach.
page.frame() — legacy, uses name or URL attribute.
// frameLocator — preferred (modern) await page.frameLocator('iframe#payment') .locator('#cardNumber').fill('4242424242424242'); // page.frame() — legacy const frame = page.frame({ name: 'paymentFrame' }); await frame.locator('#cardNumber').fill('4242424242424242');

Difference between page.locator() vs page.$()?
▼
page.$() is a shorthand for page.querySelector() — returns an ElementHandle immediately (snapshot). page.locator() is lazy and auto-waits.

🎯 Locators & Selectors 6 Questions
10
What is the benefit of using locator over elementHandle?
▼
Locator advantages:
✅ Auto-waits for actionability
✅ Lazy — re-queries DOM on every action (handles dynamic elements)
✅ Chainable — locator('.list').locator('.item')
✅ Works with expect() assertions natively
✅ Supports all Playwright built-in selectors (role, text, label, etc.)
11
How do you handle dynamic elements in Playwright?
▼
// 1. Use role-based locators (most stable) await page.getByRole('button', { name: 'Submit' }).click(); // 2. Use text locator await page.getByText('Login').click(); // 3. waitFor state await page.locator('#loader').waitFor({ state: 'hidden' }); // 4. Use filter() for dynamic list items await page.locator('.product') .filter({ hasText: 'iPhone 15' }) .click();

Difference between allTextContents() and textContent()?
▼
// textContent() — single element const text = await page.locator('h1').textContent(); // "Welcome" // allTextContents() — ALL matching elements → returns array const items = await page.locator('.list-item').allTextContents(); // ["Item 1", "Item 2", "Item 3"]
13
How to select options from a dropdown?
▼
// selectOption() — HTML select element await page.locator('#country').selectOption('India'); // by value await page.locator('#country').selectOption({ label: 'India' }); // by label await page.locator('#country').selectOption({ index: 2 }); // by index // Custom dropdown (not native select) await page.locator('#dropdown-toggle').click(); await page.locator('.dropdown-item').filter({ hasText: 'India' }).click();
14
How to handle shadow DOM in Playwright?
▼
Playwright automatically pierces shadow DOM — no special handling needed for most cases!
// Playwright auto-pierces shadow DOM await page.locator('#shadow-input').fill('test'); // If needed, use >> for explicit pierce await page.locator('custom-element >> input').fill('value');
💡 This is one of Playwright's biggest advantages over Selenium where shadow DOM is painful.

What are the built-in locator strategies in Playwright?

How do you group tests?

25
Difference between test.beforeEach and test.beforeAll?
▼
HookRunsUse case
beforeEachBefore EVERY testNavigate to page, login, reset state
afterEachAfter EVERY testCleanup, logout, close modals
beforeAllOnce before all tests in describeDB setup, create test data
afterAllOnce after all testsDB cleanup, close connections
💡 beforeAll shares state between tests — use carefully! beforeEach is safer for isolated tests.

How do you mock API responses in Playwright?
▼

What is tracing in Playwright and how is it useful?
▼
Trace records everything — DOM snapshots, network requests, console logs, screenshots — for full test debugging. Like a "time-travel debugger".
// Enable tracing await context.tracing.start({ screenshots: true, snapshots: true }); await page.goto('https://example.com'); // ... test steps ... await context.tracing.stop({ path: 'trace.zip' }); // View trace in browser npx playwright show-trace trace.zip // In config (auto trace on failure) use: { trace: 'retain-on-failure' }
33
How do you handle authentication — basic auth, bearer tokens, storageState?
▼
// 1. Basic Auth const context = await browser.newContext({ httpCredentials: { username: 'admin', password: 'pass123' } }); // 2. Bearer token via extra headers const context = await browser.newContext({ extraHTTPHeaders: { 'Authorization': 'Bearer your_token_here' } }); // 3. storageState — save login state once, reuse in all tests // Step 1: Save auth state await page.goto('/login'); await page.locator('#email').fill('user@test.com'); await page.locator('#submit').click(); await context.storageState({ path: 'auth.json' }); // Step 2: Reuse in all tests (skip login) export default { use: { storageState: 'auth.json' } };
💡 storageState is a major time-saver — login once, skip login in all other tests!
34
How to run tests in headless vs headed mode?
▼
// CLI npx playwright test // headless (default) npx playwright test --headed // headed (shows browser) npx playwright test --ui // Playwright UI mode (best for debug) // playwright.config.ts use: { headless: false, // always headed slowMo: 500, // slow down 500ms per action (debug) }
💡 Headless = no UI, faster, for CI/CD. Headed = shows browser, for debugging. UI mode = best for local development.
