Core Setup & Configuration

🔀request fixture vs APIRequestContext — Detailed Difference
Concept
request = Playwright built-in fixture — auto-created, auto-disposed per test. APIRequestContext = raw class instance you create/manage manually. Both make HTTP calls; lifecycle & isolation differ entirely.
Code 
// ✅ request fixture — auto lifecycle, good for most tests
test('GET users', async ({ request }) => {
  const res = await request.get('/api/users');
  // context is auto-disposed after test
});

// ✅ APIRequestContext — manual control, ideal for shared sessions
import { request as playwrightRequest } from '@playwright/test';

let apiContext;
test.beforeAll(async () => {
  apiContext = await playwrightRequest.newContext({
    baseURL: 'https://api.qa.myapp.com',
    extraHTTPHeaders: { 'Authorization': `Bearer ${process.env.TOKEN}` }
  });
});
test.afterAll(async () => await apiContext.dispose());
Usage
Use request fixture for stateless, isolated tests. Use APIRequestContext when you need a shared authenticated session across a suite, or when managing cookies/storage manually.
Mistake
Creating a new APIRequestContext per test — memory leak. Not calling .dispose() — leaks TCP connections. Sharing the request fixture across test files — it's already scoped per test.
Interview
"request fixture internally calls request.newContext() and disposes it in afterEach. APIRequestContext is the underlying class — use it when you need lifecycle control, cookie jar sharing, or pre-authenticated sessions."
⚙️playwright.config.js — API Testing Setup
Concept
Centralize baseURL, timeout, retry, reporter, extraHTTPHeaders per environment. For API-only projects, disable browserName and use the api project with no browser.
Code 
// playwright.config.js
import { defineConfig } from '@playwright/test';
import { config } from './src/config/env.config';

export default defineConfig({
  testDir: './tests',
  timeout: 30000,
  retries: process.env.CI ? 2 : 0,
  reporter: [['html', { open: 'never' }], ['list']],
  use: {
    baseURL: config.baseUrl,          // from env config
    extraHTTPHeaders: {
      'Content-Type': 'application/json',
      'Accept': 'application/json',
      'x-api-version': 'v2'
    },
    ignoreHTTPSErrors: true,   // for self-signed QA certs
  },
  projects: [
    { name: 'api-smoke',    testMatch: '**/*.smoke.spec.js' },
    { name: 'api-regression', testMatch: '**/*.spec.js' },
  ],
  globalSetup:    './src/global/globalSetup.js',
  globalTeardown: './src/global/globalTeardown.js',
});
Usage
baseURL from env means all requests use relative paths /api/users. Combine with projects to run smoke vs full regression on different ENV targets.
Mistake
Hardcoding URLs inside test files. Forgetting retries: 2 on CI — flaky network calls cause false failures. Setting timeout too low for slow QA environments.
Interview
"extraHTTPHeaders in playwright.config applies to the request fixture only — not to manually created APIRequestContext unless explicitly passed during newContext()."
🌍BaseURL & Environment Config (dev/qa/prod)
Concept
Drive environment selection via ENV variable. Single config file resolves the correct baseURL, credentials, and timeouts per environment.
Code 
// src/config/env.config.js
const environments = {
  dev:  { baseUrl: 'https://api.dev.myapp.com',  timeout: 5000 },
  qa:   { baseUrl: 'https://api.qa.myapp.com',   timeout: 10000 },
  prod: { baseUrl: 'https://api.myapp.com',      timeout: 8000 },
};
const env = process.env.ENV || 'qa';
if (!environments[env]) throw new Error(`Unknown ENV: ${env}`);
export const config = { ...environments[env], env };

// Run: ENV=prod npx playwright test
// CI pipeline: ENV=qa npx playwright test --project=api-smoke
Mistake
Putting prod credentials in source control. Using process.env.BASE_URL directly in tests — no validation, silent failures if env is misconfigured.
Interview
"We validate the ENV value at startup and throw early if it's invalid — fail fast is better than silent wrong-environment tests."
🌐Global Setup / Teardown for API Tests
Concept
globalSetup runs once before ALL tests. Use it to get an auth token, seed test data, or validate environment health. Result is stored in process.env for all workers.
Code 
// src/global/globalSetup.js
import { request } from '@playwright/test';
import { config } from '../config/env.config.js';

export default async function globalSetup() {
  const ctx = await request.newContext({ baseURL: config.baseUrl });
  const res = await ctx.post('/auth/login', {
    data: { email: process.env.API_USER, password: process.env.API_PASS }
  });
  if (!res.ok()) throw new Error('Global auth failed: ' + await res.text());
  const { token } = await res.json();
  process.env.AUTH_TOKEN = token;       // shared across all workers
  await ctx.dispose();
}

// src/global/globalTeardown.js
export default async function globalTeardown() {
  // revoke token, cleanup seeded data, send Slack notification, etc.
  console.log('🧹 Global teardown complete');
}
Mistake
Storing large objects in process.env — it's string-only, no objects. Instead, write to a auth.json file and read back. Forgetting that globalSetup runs in its own worker context.
Interview
"globalSetup runs before the test workers are forked — process.env changes here propagate to all workers, but imported module state does not."

APIRequestContext — Deep Dive

🔬Internal Working & Lifecycle
Concept
Wraps Node.js fetch/http under the hood. Maintains its own cookie jar, connection pool, and default headers. Lifecycle: newContext() → use → dispose().
Code 
// Lifecycle diagram in code
import { request } from '@playwright/test';

// 1. CREATE — allocates connection pool + cookie store
const ctx = await request.newContext({
  baseURL: 'https://api.qa.myapp.com',
  storageState: './auth.json',    // pre-load cookies/token
  extraHTTPHeaders: { 'x-request-id': 'automation' },
  httpCredentials: { username: 'u', password: 'p' }, // Basic Auth
});

// 2. USE — all calls share the same context (cookies persist)
const loginRes = await ctx.post('/auth/login', { data: creds });
const profileRes = await ctx.get('/users/me'); // cookie auto-sent

// 3. SAVE STATE (optional — for reuse across test files)
await ctx.storageState({ path: './auth.json' });

// 4. DISPOSE — closes connections, clears cookie jar
await ctx.dispose();
Mistake
Not calling .dispose() → leaked file descriptors + open sockets. Creating context inside a loop for each request — extreme overhead.
Interview
"storageState serializes cookies + localStorage to disk — this is how we persist login state across test files without repeating the auth flow on every test run."
🏗️Isolated vs Shared Context Strategy
Concept
Isolated = each test gets its own context (request fixture). Shared = one context for a suite (beforeAll). Choose based on whether tests share session state.
Code 
// PATTERN A — Isolated (Stateless REST APIs)
test('create user', async ({ request }) => {
  // fresh context, no pollution from other tests
  const res = await request.post('/users', { data: userData });
});

// PATTERN B — Shared (Session / Token reuse across suite)
import { test, expect } from '@playwright/test';
import { request } from '@playwright/test';

let apiCtx;
test.describe('User CRUD Suite', () => {
  test.beforeAll(async () => {
    apiCtx = await request.newContext({
      baseURL: 'https://api.qa.myapp.com',
      storageState: './auth.json' // pre-authenticated
    });
  });
  test.afterAll(async () => await apiCtx.dispose());

  test('get user list', async () => { await apiCtx.get('/users'); });
  test('update user',  async () => { await apiCtx.patch('/users/1', {...}); });
});
Usage
Shared context saves N × auth round-trip time. For a suite of 50 tests that each take 200ms to login, that's 10 seconds saved per run.
Mistake
Sharing context between parallel workers — contexts are not thread-safe across workers. Keep shared context within a single test.describe block.

HTTP Methods with Real Scenarios

📥GET — Pagination & Filtering
Code 
// Pagination — traverse all pages
async function getAllUsers(request) {
  let page = 1, all = [];
  while (true) {
    const res = await request.get('/users', {
      params: { page, limit: 50, status: 'active' }
    });
    expect(res).toBeOK();
    const { data, meta } = await res.json();
    all.push(...data);
    if (page >= meta.totalPages) break;
    page++;
  }
  return all;
}

test('all active users returned', async ({ request }) => {
  const users = await getAllUsers(request);
  expect(users.length).toBeGreaterThan(0);
  expect(users.every(u => u.status === 'active')).toBe(true);
});
Mistake
Only testing page 1. Not validating meta.totalCount matches actual items fetched. Ignoring edge case: empty data array (zero results).
Interview
"params in Playwright request are auto-encoded and appended to the URL — no manual URLSearchParams needed."
📤POST — Dynamic Payload Creation
Code 
// Test data factory + POST
import { buildUser } from '../factories/user.factory';

test('create user with dynamic payload', async ({ request }) => {
  const payload = buildUser({ role: 'admin', verified: true });

  const res = await request.post('/users', {
    data: payload,
    headers: { 'Idempotency-Key': payload.email } // prevent duplicate on retry
  });

  expect(res.status()).toBe(201);
  const body = await res.json();
  expect(body).toMatchObject({
    email: payload.email,
    role:  'admin',
    id:    expect.any(String)
  });
});

// src/factories/user.factory.js
import { faker } from '@faker-js/faker';
export const buildUser = (overrides = {}) => ({
  name:     faker.person().fullName(),
  email:    faker.internet().email(),
  role:     'viewer',
  verified: false,
  ...overrides
});
Mistake
Hardcoded email in POST payload — duplicate key error on second run. Not asserting 201 specifically (only ok() which includes 200).
🔄PUT vs PATCH — Difference + Usage
Concept
PUT = full replacement (send complete resource). PATCH = partial update (send only changed fields). Missing fields in PUT = nulled; missing in PATCH = untouched.
Code 
// PUT — full replacement (all fields required)
test('PUT replaces entire user object', async ({ request }) => {
  const res = await request.put(`/users/${userId}`, {
    data: { name: 'Amir Khan', email: 'amir@qa.com', role: 'admin' }
  });
  expect(res.status()).toBe(200);
  const body = await res.json();
  expect(body.role).toBe('admin');
});

// PATCH — partial update (only changed fields)
test('PATCH updates only role field', async ({ request }) => {
  // Capture pre-state
  const before = await (await request.get(`/users/${userId}`)).json();

  const res = await request.patch(`/users/${userId}`, {
    data: { role: 'viewer' } // ONLY role changes
  });
  expect(res.status()).toBe(200);
  const after = await res.json();
  expect(after.role).toBe('viewer');
  expect(after.name).toBe(before.name); // name must be unchanged
});
Interview
"Always validate the unchanged fields after PATCH — that's the real assertion. Missing this catches bugs where PATCH accidentally nullifies unspecified fields."
🗑️DELETE — Cleanup Strategy in Automation
Code 
test('delete user — full lifecycle', async ({ request }) => {
  // Setup — create resource for this test
  const createRes = await request.post('/users', { data: buildUser() });
  const { id } = await createRes.json();

  // DELETE
  const delRes = await request.delete(`/users/${id}`);
  expect(delRes.status()).toBe(204); // No Content

  // Verify — 404 on subsequent GET
  const getRes = await request.get(`/users/${id}`);
  expect(getRes.status()).toBe(404);

  // Idempotency — DELETE again should still be 404
  const del2 = await request.delete(`/users/${id}`);
  expect(del2.status()).toBe(404); // not 500!
});

// Cleanup pattern — afterEach tracking
const createdIds = [];
test.afterEach(async ({ request }) => {
  for (const id of createdIds) {
    await request.delete(`/users/${id}`).catch(() => {}); // best-effort
  }
  createdIds.length = 0;
});
Mistake
Only checking 204 but not verifying GET returns 404. Not testing idempotency (double DELETE). Cleanup in afterAll instead of afterEach — if suite fails mid-way, data leaks.

🔑Headers — Authorization & Dynamic Tokens
Code 
// Dynamic token in each request
const getAuthHeader = () => ({
  'Authorization': `Bearer ${process.env.AUTH_TOKEN}`,
  'x-correlation-id': crypto.randomUUID(),  // traceability
  'x-test-run': process.env.CI_RUN_ID || 'local',
});

// Per-request header override
const res = await request.get('/admin/users', {
  headers: {
    ...getAuthHeader(),
    'x-admin-key': process.env.ADMIN_KEY
  }
});

// Context-level default (applies to all calls in this context)
const ctx = await request.newContext({
  extraHTTPHeaders: getAuthHeader()   // set once, used everywhere
});
Mistake
Hardcoding token strings in tests. Not rotating x-correlation-id — makes production log tracing impossible.
📦Body Types — JSON, form-data, x-www-form-urlencoded
Code 
// 1. JSON body (default with 'data')
await request.post('/users', {
  data: { name: 'Amir', email: 'a@qa.com' }  // auto Content-Type: application/json
});

// 2. form-data (file upload)
import { readFileSync } from 'fs';
await request.post('/upload', {
  multipart: {
    file: {
      name: 'report.pdf',
      mimeType: 'application/pdf',
      buffer: readFileSync('./fixtures/report.pdf')
    },
    category: 'finance'   // additional form field
  }
});

// 3. x-www-form-urlencoded (legacy / OAuth token endpoints)
await request.post('/oauth/token', {
  form: {
    grant_type:    'client_credentials',
    client_id:     process.env.CLIENT_ID,
    client_secret: process.env.CLIENT_SECRET,
    scope:         'read:users write:users'
  }
  // auto Content-Type: application/x-www-form-urlencoded
});
Interview
"data = JSON, form = urlencoded, multipart = multipart/form-data. Playwright sets Content-Type automatically for each — don't set it manually or it may conflict."

Authentication — Real-World Patterns

🔐Bearer Token — Generate & Reuse Pattern
Code 
// src/helpers/auth.helper.js
import { request } from '@playwright/test';
import { config } from '../config/env.config.js';

let cachedToken = null;
let tokenExpiry = 0;

export async function getToken() {
  if (cachedToken && Date.now() < tokenExpiry) return cachedToken;

  const ctx = await request.newContext({ baseURL: config.baseUrl });
  const res = await ctx.post('/auth/token', {
    form: {
      grant_type: 'client_credentials',
      client_id:  process.env.CLIENT_ID,
      client_secret: process.env.CLIENT_SECRET
    }
  });
  const { access_token, expires_in } = await res.json();
  cachedToken = access_token;
  tokenExpiry = Date.now() + (expires_in - 60) * 1000; // 60s buffer
  await ctx.dispose();
  return cachedToken;
}

// Usage in test
test('authenticated call', async ({ request }) => {
  const token = await getToken();
  const res   = await request.get('/profile', {
    headers: { 'Authorization': `Bearer ${token}` }
  });
  expect(res).toBeOK();
});
Mistake
Fetching a new token per test (N × auth latency). Not accounting for token expiry mid-run — tests fail with 401 after 1 hour if token lifetime is short.
Interview
"We cache the token with a 60-second expiry buffer to handle clock skew between our test runner and the auth server."
🗝️API Key, Session & storageState Pattern
Code 
// API Key — header or query param
const res = await request.get('/data', {
  headers: { 'X-API-Key': process.env.API_KEY }
  // OR: params: { api_key: process.env.API_KEY }
});

// Session via storageState — save after login, reuse across files

await ctx.post('/auth/login', { data: creds });
await ctx.storageState({ path: './auth-state/admin.json' });

// Step 2: In tests — load saved state
const authedCtx = await request.newContext({
  baseURL: config.baseUrl,
  storageState: './auth-state/admin.json'
});
// All cookies from login are automatically sent
const profile = await authedCtx.get('/me');
Mistake
Committing auth-state/admin.json to git — contains session cookies. Add to .gitignore.

Response Handling — Deep

📊status(), ok(), headers() & JSON Parsing
Code 
test('response deep dive', async ({ request }) => {
  const res = await request.get('/users/42');

  // status + ok
  console.log(res.status());        // 200
  console.log(res.ok());            // true (200-299)
  console.log(res.statusText());    // "OK"
  console.log(res.url());           // actual URL hit

  // headers
  const headers = res.headers();     // returns plain object
  expect(headers['content-type']).toContain('application/json');
  expect(headers['x-request-id']).toBeDefined(); // traceability

  // JSON — always await, call once and store
  const body = await res.json();
  expect(body.id).toBe(42);

  // Response time — custom validation
  const timing = res.headers()['x-response-time']; // if server sends it
  const start  = Date.now();
  const slow   = await request.get('/heavy-report');
  const ms     = Date.now() - start;
  expect(ms).toBeLessThan(3000); // SLA: under 3s
});
Mistake
Calling res.json() multiple times — it reads the stream, second call returns empty. Store result in a variable. Using res.body() and then res.json() — same issue.
Interview
"ok() returns true for any 2xx status — but in POST, 201 ≠ 200. Always use status() for precise status code assertion in CRUD tests."
📦Handling Large / Complex Responses
Code 
// Large response — extract only what you need
test('validate report summary in large response', async ({ request }) => {
  const res  = await request.get('/reports/annual?year=2024');
  const body = await res.json();

  // Destructure only needed fields
  const { summary, status, generatedAt } = body;

  expect(status).toBe('completed');
  expect(summary.totalRevenue).toBeGreaterThan(0);
  expect(new Date(generatedAt)).toBeInstanceOf(Date);

  // Find in array — avoid full array assertion
  const q4 = body.quarters.find(q => q.name === 'Q4');
  expect(q4.growth).toBeGreaterThan(0.05); // 5%+ growth
});
Mistake
expect(body).toEqual(hugeExpectedObject) — any tiny schema change breaks test. Use targeted assertions on specific fields.

Assertions — Advanced

✅Advanced Assertion Patterns
Code 
// Status codes
expect(res.status()).toBe(201);
expect([200, 201]).toContain(res.status());  // either OK

// Deep nested object validation
expect(body).toMatchObject({
  user: {
    profile: {
      address: {
        city: 'Noida',
        pincode: expect.any(String)
      }
    },
    roles: expect.arrayContaining(['admin'])
  }
});

// Partial match — extra fields OK
expect(body.user).toMatchObject({ email: 'amir@qa.com' });

// Array shape
expect(body.items).toHaveLength(10);
expect(body.items[0]).toMatchObject({
  id:    expect.any(String),
  price: expect.any(Number),
});

// Custom assertion util
function assertPagination(meta, { page, limit }) {
  expect(meta.currentPage).toBe(page);
  expect(meta.perPage).toBe(limit);
  expect(meta.totalPages).toBeGreaterThanOrEqual(1);
  expect(meta.totalCount).toBeGreaterThanOrEqual(0);
}
Interview
"toMatchObject does partial deep matching — ideal for API responses where server adds computed fields (id, createdAt) you don't control. toEqual would fail on those."
Mistake
Using toEqual for full response comparison — will break whenever server adds new optional fields. Prefer toMatchObject for response bodies.
🔍Schema Validation with JSON Schema
Concept
Use ajv (JSON Schema validator) for contract testing — validate structure without caring about values. Catches breaking API changes early.
Code 
// npm install ajv
import Ajv from 'ajv';
const ajv = new Ajv();

const userSchema = {
  type: 'object',
  required: ['id', 'email', 'role'],
  properties: {
    id:    { type: 'string' },
    email: { type: 'string', format: 'email' },
    role:  { type: 'string', enum: ['admin', 'viewer'] },
    age:   { type: 'integer', minimum: 0 }
  },
  additionalProperties: false  // strict — no surprise fields
};

test('user schema is valid', async ({ request }) => {
  const body = await (await request.get('/users/1')).json();
  const valid = ajv.validate(userSchema, body);
  expect(valid, ajv.errorsText()).toBe(true);
});
Interview
"Schema validation as contract testing — we catch API breaking changes before they reach UI tests. It's the cheapest integration test you can write."

Error Handling & Debugging

🔁Retry Logic & 4xx/5xx Handling
Code 
// Utility: retry with exponential backoff
async function retryRequest(fn, { retries = 3, delayMs = 500 } = {}) {
  let attempt = 0;
  while (true) {
    try {
      const res = await fn();
      if (res.status() === 429 || res.status() >= 500) {
        if (++attempt > retries) throw new Error(`Failed after ${retries} retries: ${res.status()}`);
        await new Promise(r => setTimeout(r, delayMs * 2 ** attempt));
        continue;
      }
      return res;
    } catch (e) {
      if (++attempt > retries) throw e;
      await new Promise(r => setTimeout(r, delayMs * 2 ** attempt));
    }
  }
}

// Test: 4xx should contain error message
test('400 Bad Request has error detail', async ({ request }) => {
  const res = await request.post('/users', { data: { email: 'bad' } });
  expect(res.status()).toBe(400);
  const err = await res.json();
  expect(err.message).toContain('email');
  expect(err.code).toBeDefined();  // e.g. "VALIDATION_ERROR"
});
Interview
"We retry on 429 and 5xx only — not on 4xx, because those are test/data bugs, not transient. Retrying on 4xx masks real failures."
🪵Logging Request & Response for Debugging
Code 
// Logging wrapper — wraps any request method
export async function loggedRequest(fn, label = '') {
  const start = Date.now();
  let res;
  try {
    res = await fn();
    const ms   = Date.now() - start;
    const body = await res.text();
    console.log(`[API] ${label} → ${res.status()} (${ms}ms)\n` +
      `  URL: ${res.url()}\n` +
      `  Body: ${body.slice(0, 500)}`);
    return { res, body: JSON.parse(body) };
  } catch (e) {
    console.error(`[API] ${label} FAILED:`, e.message);
    throw e;
  }
}

// Usage
const { res, body } = await loggedRequest(
  () => request.post('/payment', { data: payload }),
  'POST /payment'
);

// Built-in: DEBUG=pw:api npx playwright test  ← logs all HTTP
Usage
Set DEBUG=pw:api env variable to get Playwright's built-in HTTP logging. Use the wrapper for business-level logging in your CI reports.
Mistake
Logging entire response body in production CI — may expose PII/secrets. Truncate with .slice(0, 500) or mask sensitive fields.

Parallel Execution

⚡Parallel API Tests — Safe Data Strategy
Concept
Playwright runs test files in parallel by default. API tests must use unique test data per worker to avoid conflicts (unique email, userId, etc.).
Code 
// playwright.config.js
export default defineConfig({
  workers: process.env.CI ? 4 : 2,         // parallel workers
  fullyParallel: true,                       // tests within file also parallel
  // Use test.describe.configure({ mode: 'serial' }) for dependent tests
});

// Unique data per test — worker index + timestamp
test('parallel safe user creation', async ({ request }, testInfo) => {
  const uniqueSuffix = `${testInfo.workerIndex}_${Date.now()}`;
  const payload = {
    email: `user_${uniqueSuffix}@test.com`,
    name:  `Test User ${uniqueSuffix}`
  };
  const res = await request.post('/users', { data: payload });
  expect(res.status()).toBe(201);
});

// Serial mode for dependent tests (login → action → logout)
test.describe.configure({ mode: 'serial' });
test.describe('Payment flow', () => {
  let orderId;
  test('create order',  async ({ request }) => { orderId = ...; });
  test('pay order',     async ({ request }) => { /* uses orderId */ });
  test('verify payment', async ({ request }) => { /* sequential */ });
});
Mistake
Shared global state between parallel workers (like a module-level let userId). Each worker is a separate Node.js process — module state is not shared.
Interview
"testInfo.workerIndex gives worker ID (0,1,2…). Combined with timestamp it guarantees uniqueness even when workers start at the same millisecond."

Framework Design — VERY IMPORTANT

🏛️ API Service Layer — Client Class Architecture
// src/services/UserService.js — API Client class
export class UserService {
  constructor(request) {
    this.request = request;
    this.base = '/api/v2/users';
  }

  async getAll({ page = 1, limit = 20, status } = {}) {
    return this.request.get(this.base, { params: { page, limit, status } });
  }
  async getById(id)       { return this.request.get(`${this.base}/${id}`); }
  async create(data)      { return this.request.post(this.base, { data }); }
  async update(id, data) { return this.request.patch(`${this.base}/${id}`, { data }); }
  async replace(id, data){ return this.request.put(`${this.base}/${id}`, { data }); }
  async remove(id)       { return this.request.delete(`${this.base}/${id}`); }

  // Domain-specific method
  async promoteToAdmin(id) {
    return this.request.post(`${this.base}/${id}/promote`);
  }

  // With response parsing (shorthand)
  async createAndParse(data) {
    const res = await this.create(data);
    expect(res.status()).toBe(201);
    return res.json();
  }
}

Best Practices

🧹

Never Hardcode URLs or Tokens

All URLs via config.baseUrl, all secrets via process.env. Any hardcoded value = a maintenance nightmare at scale.

🎯

Assert What Matters, Not Everything

3 precise assertions beat 20 shallow ones. Focus on: status code, key field value, response structure (schema). Skip timestamps and IDs you don't control.

🧪

Test Data Isolation

Each test owns its data. Create in setup, cleanup in teardown. Use afterEach cleanup tracking arrays. Never reuse data between tests.

🔢

One Concern Per Test

Don't test CRUD in one test. create user, get user, delete user = 3 separate tests. Easier to debug, faster to rerun.

📝

Use test.step() for Clarity

await test.step('Create user', async () => {...}) — shows in HTML report as nested steps. Makes complex test flows readable without comments.

🏷️

Tag Tests for Selective Running

test('login @smoke @critical', ...) → npx playwright test --grep @smoke. Use tags for smoke, regression, blocker, slow, api-only.

📊

HTML Report + Allure

Enable built-in HTML reporter for local runs. Add Allure for CI dashboards. Attach request/response body to failed tests via test.info().attach().

🔒

Security Test Coverage

Test for: missing Authorization → 401, wrong role → 403, another user's resource → 403/404, expired token → 401. These are free regression tests.

⏱️

Performance Baselines in API Tests

Wrap time-sensitive calls with Date.now(). Assert toBeLessThan(2000) for critical endpoints. Catch regressions before UAT.

🔄

CI/CD Integration

Run ENV=qa npx playwright test --project=api-smoke on every PR. Full regression nightly. Never block deploy on flaky non-critical tests — use retries: 2.

📦

Service Layer = Maintainability

If the API endpoint changes, update one file (UserService.js), not 50 test files. This is the single biggest maintainability win in large frameworks.

🧠

Contract Testing First

Run schema (AJV) validation on every endpoint before value assertions. If schema fails → data assertions are meaningless. Fail fast, fail clear.
